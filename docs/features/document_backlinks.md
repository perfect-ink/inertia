# Backlinks

## What it does
- A "Linked from N documents" section sits at the bottom of a document, under its content and inside the same scrolling page (Alex, 2026-11-09). It lists the documents in the same Space that link to it: each row is a link to that document with its type icon, its title and, when it is in a folder, where it lives ("Album / Songs"). The section is hidden while loading and when nothing links here (design principle 9), so a document nobody links to shows nothing extra.
- A document "links" to another through a link in its text whose address is the other document's id path, which includes a link to a heading in it (`/documents/12#launch-plan`, `heading_links.md`), the hash router's `#/documents/12`, and either behind a scheme and host (`https://app.example.com/documents/12`). The path has to start with `documents/<id>`: links are matched by id, never by title or folder, so renaming or moving a document does not break them, and folder slugs in front of a path (the hierarchical URLs of `backlog/hierarchical-urls`, where heading links keep using id paths) are not mistaken for an id (`/product/documents/5` is not document 5); or through an inline document link node (`documentLink`, the `[[` link of `docs/backlog/link-to-another-document.md`). The node is recognised by name already, so those links start to count the day the editor can create them, with no change here. A link written as a hierarchical path (`/product/requirements`, the address copied from the browser's address bar once the page has rewritten itself, `docs/features/hierarchical_urls.md`) counts too: see Links written as paths below. A link to itself, to a missing document, or to a document in another Space is ignored.
- The list follows the links as documents are saved, including saves from a collaborative session (the collab server saves through the same Rails endpoint).

## API and models
- Table `document_links` (`source_document_id`, `target_document_id`, both foreign keys to `documents`; unique on the pair; migration `20261108130001_create_document_links.rb`). A row says "source links to target".
- `DocumentLink.refresh!(document)` (`backend/app/models/document_link.rb`) rebuilds a document's outgoing rows from its content: `target_ids_in` walks the editor JSON for `documentLink` nodes and link marks, keeps only documents of the same Space, and adds or removes the difference. `Document` calls it after every save that changes the content, the folder (a move to another Space drops links to the old one) or is the first save, only for `doc_type: document`. Rows are inserted with `insert_all`, so two saves racing never fail on the unique pair. Deleting either document deletes its rows.
- `GET /api/v1/documents/:id/backlinks` returns the linking documents (`Document#backlinks`: same Space only, by title; the same fields as the document list, no content). Frontend: `DocumentApi#backlinks` and `useBacklinks` in `frontend/src/api/documents.ts` (refetched every time a document opens), `components/DocumentBacklinks.tsx` (+ `.scss`), `data/backlink.ts`, shown by `view/document/DocumentScreen.tsx`.
- Links written as paths. `LinkAddress.slug_path` (`backend/app/services/link_address.rb`, pure) reads an href as a slug path when it is relative (`/product/requirements`, `/product/requirements#intro`, `?query`, the hash router's `#/product/requirements`) or is behind the scheme and host of one of the app's own origins (`https://inertia.it.com/product/requirements`). The origins are `APP_URL`, `WEB_URL` and the http(s) ones of `CORS_ORIGINS`, read once at boot by `config/initializers/app_origins.rb` (`Rails.configuration.x.app_origins`; no new variable); hosts are compared without scheme and default port, and the host is the one after any `user@`. Case and a trailing slash do not matter. Not read as paths: another site's address, an id path (`/documents/12`, `/folders/3`, so those cost no lookup), an app page (a first segment in `Slug::RESERVED`, such as `/tasks`), a bare `product/requirements`, and anything with a segment that could not be a slug (`file.pdf`, `%2e%2e`).
- `DocumentLink.targets_in(content)` walks the content once and returns `Targets` (`ids` for `documentLink` nodes and id addresses, `paths` for the distinct slug paths, at most `MAX_PATH_LOOKUPS` = 100). `refresh!` then resolves each path once with `PathResolver.find(document's Space, segments)`, which follows old paths of renamed or moved items, and keeps only a result that is a document (any type: text, sheet, Collection, file). A path that names a folder or nothing adds no backlink. Because the lookup is in the document's own Space only, a path to another Space's item finds nothing there (and when this Space holds the same path, that one wins, as it does when opening it in the app). Rows are still by id, so renaming or moving the target afterwards keeps the backlink, and the path is looked up again only when the source document is saved.
- `rails document_links:rebuild` (`backend/lib/tasks/document_links.rake`, `DocumentLink.rebuild_all!`) records the links of documents saved before this existed. Safe to run again.

## Who can view and change
Anyone who can open a document can read its backlinks (the lookup is by the Spaces the user belongs to, like `GET /api/v1/documents/:id`). Nobody edits the rows: they only follow document content. A failed request shows the API client's error notice.

## Known limits
- The panel appears on documents only. The endpoint works for any file type (a sheet, Collection or uploaded file can be linked to by address), but their screens do not show it yet (`docs/backlog/backlinks-on-sheets-collections-and-files.md`). Links written inside sheets and Collections are not tracked.
- Documents saved before this shipped have no rows until saved again or `rails document_links:rebuild` is run once after deploy.
- An address on any host whose path starts with `/documents/<id>` counts, even on another site, as long as that id is a document in the same Space.
- The panel lists titles and places, with no snippet of where the link sits, and does not say whether the link is to a heading.
- A slug path is looked up when its source document is saved, not when the target changes: a link whose path named nothing when it was saved does not appear if a document is later created at that path, until the source is saved again or `rails document_links:rebuild` is run. A path whose slug is later taken by another document points at that document the next time the source is saved, as clicking it would. At most 100 distinct paths per save are looked up. A pasted path behind a host that is not in `APP_URL`, `WEB_URL` or `CORS_ORIGINS` (a second domain, a staging site) is not read. The panel's own links use the id path (`/documents/<id>`), which opens and rewrites to the hierarchical path.
- `link-to-another-document` adds the `documentLink` node. Nothing in this feature needs to change when it merges; check by adding a `[[` link and finding it listed on the target.
